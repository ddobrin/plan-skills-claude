the plan swarm · plan-swarm@2.1

A swarm of role agents that drives one change from idea to commit

SWARM ROLES Do the work product-owner writes a Gherkin spec · architect writes a micro-stepped plan, read-only on source · engineer builds it under TDD · auditor verifies against the plan and runs the suite.
ADVERSARIAL VALIDATORS Attack the artifact Three panels sit at the phase boundaries — spec, plan, diff. Each runs 3 skeptics on partitioned lenses and keeps only what a 2-of-3 majority confirms.
DELIBERATIVE PANELS Improve the artifact The generative counterpart: delegates holding deliberately disjoint context argue to consensus on one revised spec or plan. Optional, before validation.

Files under plans/ — never chat messages — are the single source of truth. Agents are handed file paths, not summaries.

the framework · the practice

Graph engineering is a loop, not a diagram

01 · DECLARE One file, or none Every node, every edge, every routing condition — in one machine-readable artifact. Anything else describing the shape is a copy.
02 · GENERATE Never transcribe Diagrams and docs are emitted from the declaration, between markers. A hand-drawn diagram is a second source of truth waiting to drift.
03 · VALIDATE Resolve against disk Does every declared node exist? Does every edge land somewhere? Is every node reachable? A violation is a non-zero exit, not a review comment.
04 · DRIFT-CHECK Close the loop CI regenerates and fails if the output differs. Skip this one step and the declaration quietly decays back into documentation.

Nothing in this loop executes the graph. Graph engineering is a build-time discipline — it makes the shape of a system reviewable, not runnable.

the framework · the assertions

Stripped of the vocabulary, graph engineering asserts three things

TOPOLOGY · P1 The topology is an explicit artifact Which nodes exist, what routes between them, under what condition — readable as one thing, and generated rather than transcribed. A diagram you maintain by hand is a second source of truth waiting to drift.
CONTEXT · P2 Each node gets its own clean context Its own prompt, its own tools, its own evidence — so one agent's working memory does not pollute another's. The unit of isolation is the node, not the conversation.
STATE · P3 State crosses boundaries only through declared edges A schema, not a directory convention. What a node may read and write is written down and checkable — not a sentence in a prompt asking it to behave.
what it cannot express

A topology can show you that three branches run in parallel. It cannot show you whether those branches are independent — and that is the property that decides whether a voting gate means anything.

the declaration

Who writes graph.json, and what it actually is

WHO · a human, by hand It is not generated from anything. Someone edits it when the swarm's shape changes, then runs sync. Its own header says so: “edit this file, then regenerate — never hand-edit a rendered diagram.”
WHY · to break a three-way tie The topology used to live in two READMEs and in the orchestrator's control flow. All three claimed to describe the same lifecycle; none was authoritative, so nothing could detect that they had drifted apart.
WHAT · a manifest, not a runtime Nothing executes it. graph.json is the AST, starter is the eval loop (it is not a node — it is what walks the graph), graph.py is the type checker. An edge is enforced at review time by CI, not at runtime by construction.

enforcement

Every invariant sits on one of three rungs

5 declaredWritten into graph.json as a named invariant.
3 checkedgraph.py exits 1 the moment it is broken.
2 trustedDeclared and labelled as prose — no check exists.

the five, and the rung each lands on

✔
Only starter runs git commit. violating it → node 'x' declares it commits but is not held by starter · exit 1
✔
Only engineer and simplifier write repository source. violating it → node 'x' declares it writes repository source · exit 1
✔
Every panel declares n distinct lenses — identical prompts are a defect, not a config. violating it → lens declared but absent from <prompt_file> · exit 1
○
Human gates cannot run inside a scripted workflow. unenforceable — no file records how the swarm was invoked
○
Agents are dispatched with file paths, never a prose summary. unenforceable — the violation is a message, and messages are not on disk

what moving a rung feels like

“Read-only on source” stopped being something a model is asked to remember and became something a script refuses to let pass.

One test decides the rung: does breaking it leave a mark in a file? The last two can only be broken in transit — in a dispatch message that nobody writes down.

the edge of enforcement

Three ways past the ladder entirely

01 · NOT DECLARED The check runs one way validate walks the declaration and asks “is this on disk?” Nothing walks disk and asks “is this declared?” 20 skills exist; 13 are declared. Add one, forget to declare it, and the build stays green.
02 · NOT EXPRESSIBLE Independence has no syntax The highest-value change here — giving each panel's three skeptics disjoint evidence — is not something any topology language can express. Independence is a property of the information flowing through the edges, not of their shape.
03 · NOT MEASURED The payoff is an inference That partitioned lenses catch more than identical ones is believed, not shown. Falsify it: re-run one shipped milestone both ways and diff the confirmed findings. If cross_lens is zero, the partition bought nothing.

Graph engineering named two real defects here — a drifted topology and undeclared state — and both are now on rung 2. It was silent on the third, which is the one most likely to change what the gates actually catch.
