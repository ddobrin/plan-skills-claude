The three principles

What conformance is being measured against

Stripped of the vocabulary, graph engineering asserts three things. Every claim on this page is tagged with the one it serves — and one important change on this branch serves none of them, which is stated rather than hidden.

P1 The topology is an explicit artifact Which nodes exist, what routes between them, under what condition — readable as one thing, generated rather than transcribed.
P2 Each node gets its own clean context Its own prompt, its own tools, its own evidence — so one agent's working memory does not pollute another's.
P3 State crosses boundaries only through declared edges A schema, not a directory convention. What a node may read and write is written down and checkable.

P1 · the whole thing

The complete graph, generated from the file that defines it

This is not a drawing of the swarm. It is plugins/plan/graph.json, rendered by graph.py render svg — 16 nodes, 25 edges, every label and lens read out of the declaration. Re-run the command after editing the file and this picture changes with it; there is no version of it that can be right while the declaration is wrong.

Three of the sixteen nodes carry a lens roster, and both gates are drawn in the same colour they hold in the state file. Nothing in this figure was typed by hand — which is the entire claim of P1, made checkable: graph.py sync --check fails the build when a generated block and its source disagree.

P1 · the declaration

What is inside graph.json, and what each part binds to

The file is not documentation that happens to be machine-readable. Every field below resolves to something on disk, and validate fails when the resolution fails.

P3 · mechanism

A skill is now a node with declared edges

Every skill's authority used to live in prose — “read-only on source”, “never commits”. Those sentences are still there, but the same facts are now declared in graph.json where a script can read them. architect is the clearest case: it reads two things, writes three, and is explicitly denied one.

P2 · mechanism

Clean context, extended inside the fan-out

Per-node isolation was already this swarm's strongest property. What was missing was isolation within a node's fan-out: each panel dispatched one prompt three times, so three branches shared one prompt, one model and one reading assignment. Each panel now hands its three skeptics disjoint evidence.

The pre-flight check that keeps it honest

Every panel run must first pass the asymmetry test: name one finding only that lens could reach. If you cannot, merge it and run two — a panel of near-clones is worse than an honest pair, because it manufactures corroboration. The test is lifted in spirit from plan-deliberator's Core Principle 1, which had it right before the validators did.

skills/starterorchestrator P1P3

What changed

The state machine now dispatches the validators and deliberators that both READMEs always documented — previously it went product-owner → architect and skipped every gate. Two new contract clauses: the topology is declared, not remembered (follow graph.json) and the phase is read, not inferred (read state.json). The engineer⇄auditor cycle gained a 3-round cap.

New boundary

“Never skip a gate silently. If you deliberately skip a validator or a deliberator, say so and record it in state.json. An unrecorded skipped gate is indistinguishable from a gate that passed.”

Still true

  • ✓ only node that runs git commit
  • ✓ holds both human gates
  • ✓ dispatches file paths, not summaries
Why it matters most: by the Berkeley multi-agent failure taxonomy, a documented-but-undispatched gate is a system design failure — the 44.2% category, against 2.7% for anything aggregation-related. This was the single largest defect on the branch.
agents/supervisoragent P1P3

What changed

The initialPrompt bootstrap no longer inspects the milestone directory to guess a phase. It reads state.json, reconciles it against graph.json, and reports any gate recorded as skipped or outstanding before recommending an action.

New agent note

“The topology is a file, not a memory.” Skipping a declared node is a decision to state out loud and record — not one to make silently. The README diagrams are generated; never hand-edit them.

Inherited: the body still delegates to ${CLAUDE_PLUGIN_ROOT}/skills/starter/SKILL.md, so the state machine stays single-sourced between the skill and agent families rather than being restated.
plugins/plan/graph.jsonnew · declaration P1P3

What it holds

16 nodes with kind, phase, skill, agent and alternatives; 25 edges with conditions and labels; 2 gates; 5 invariants; per-node reads, writes and must_not_write; and each panel's lens roster with its asymmetry statement.

Invariants declared

  • · only starter commits
  • · only engineer + simplifier write source
  • · identical prompts are a defect, not a config
  • · human gates cannot run inside a workflow
  • · dispatch file paths, never summaries
Deliberate deviation: the original recommendation put reads:/writes: in each skill's frontmatter. They live here instead — putting them in both places would create a second hand-maintained copy of the same facts, which is exactly the defect P1 exists to prevent.
lib/graph/graph.pynew · tooling P1P2P3

What it does

Stdlib only, so it runs wherever the plugin is installed and on either harness. validate checks the declaration against disk; render ascii|mermaid draws the graph; sync rewrites the generated blocks in both READMEs; sync --check exits non-zero when one is stale.

Failures it produces

  • ✗ declared skill or agent missing from disk
  • ✗ edge pointing at an unknown node
  • ✗ node with no inbound edge
  • ✗ node claiming write authority it lacks
  • ✗ lens declared but absent from its prompt
  • ✗ prompt file reverted to identical dispatch
Both new checks were negative-tested. Renaming a lens in graph.json, and appending “dispatch this three times, unchanged” to a prompt file, each produce a named error and exit 1.
lib/graph/STATE.mdnew · schema P3

What it defines

state.json per milestone: run_id, phase, gate decisions, per-node status with report paths, and per-group tasks, audit rounds and commit SHAs. Written only by starter; read by everyone resuming.

Two fields worth knowing

cross_lens — how many confirmed findings were reached by more than one lens. The number that says whether a panel produced independent corroboration or one opinion twice.

reason — required whenever a node's status is skipped. Absence of a report is otherwise ambiguous between not-run, crashed and deliberately skipped.

Honest accounting

What does not fit the framework

The highest-value change on this branch — lens partitioning — is tagged P2 above, and that tag is generous. It satisfies “clean context per node” only if you accept that a fan-out branch counts as a node. The reason to do it comes from somewhere else entirely: correlated judge panels run 8–22 points below the independent-voting ideal, and no aggregation algorithm recovers more than 11% of that gap. That is a property of the information flowing through the edges, and no topology language can express it.

So the sheet above is honest in both directions. Graph engineering named two real defects — the drifted topology and the undeclared state — and both are now fixed and machine-checked. It was silent on the third, which is the one most likely to change what the gates actually catch.

And nothing is measured yet. That the partitioned lenses find more than three identical ones is an inference from the literature until a shipped milestone is re-run both ways and the confirmed sets are diffed.
