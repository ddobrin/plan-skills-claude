Walkthrough: the plan‑swarm@3.0 changes

A reviewer's guide to what changed between plan‑swarm@2.1 and 3.0, why each part exists, and where to look first.

Baseline a54fa10 Commit 470eaba (feat(plan): plan‑swarm@3.0…) + follow‑up fixes in the working tree (Part C) Plugin 2.1 → 3.0.0
In 2.1 the swarm's rules lived in prompts: "only the auditor commits", "stop for approval". In 3.0 they are enforced. A small standard‑library control plane turns six exact approval phrases into single‑use approvals, refuses every commit, push, or tag without one, and records each approval in a ledger that is committed with the change it authorizes. Around it the lifecycle gained an intent inbox, risk tiers, parallel worktrees, a PR stage, report‑only validators, metrics, and an eval suite. Each role's prompt now has one source file, and the agent and skill forms are generated from it.

Suggested review order

  1. The contract: plugins/plan/topology.md (the 3.0 graph) and the approval phrases in lib/approve.py's docstring. Everything else implements these.
  2. The authority: lib/gate.py, read top‑down: module docstring (threat model) → check_bash → check_git → check_commit / check_push / check_tag → git_hook / pre_push. Then lib/swarmgit.py (store, nonces, ledger).
  3. The proof: lib/tests/test_security.py reads as a list of attacks that must stay refused, and test_gate.py as the policy table.
  4. The orchestration: roles/supervisor.md (the 3.0 state machine), then the role deltas in A4.
  5. The mechanics: lib/render_roles.py + one role file, then the helpers (worktree.py, tier.py, prbody.py).
  6. Behavior end to end: usage-e2e.html, a real run of every stage.

Skip the generated agents/ and skills/<role>/SKILL.md diffs: review the role source instead. CI's render_roles.py --check guarantees the generated files match it.

A1 · One source per role

Why. In 2.1 every role existed twice (agents/X.md and skills/X/SKILL.md) and had to be kept in sync by hand. Every 3.0 prompt change would have doubled the work and risked drift.

What. roles/{name}.md holds both front‑matter blocks verbatim plus one body. Shared text renders into both forms; @agent / @skill blocks render into one. lib/render_roles.py writes the forms; --check fails CI if they are stale.

<!-- @agent:frontmatter -->          ← agent front matter, copied as-is (name, description, model, color, tools)
<!-- @skill:frontmatter -->          ← skill front matter, copied as-is
<!-- @body -->
shared text                          → both forms
<!-- @agent --> … <!-- @end -->      → agent only
<!-- @skill --> … <!-- @end -->      → skill only

How it was proven safe. The migration was done first with no behavior change: the first render reproduced all 27 existing files byte for byte. Only then were prompts changed. The supervisor and auditor were merged into a single shared body; the other roles keep their form‑specific blocks and gained shared 3.0 sections. simplifier gained an agent form (14 agents, up from 13).

A2 · The control plane

Why. The feasibility review's top finding: governance was prompt‑only. Nothing stopped an engineer with Bash from committing, and approvals were words in chat.

PieceWhat to look for
hooks/hooks.jsonSessionStart → health.py, UserPromptSubmit → approve.py, PreToolUse (Bash, Write, Edit, MultiEdit, NotebookEdit, Agent, Task) → gate.py.
lib/approve.pyExact whole‑prompt grammar for six phrases. Writes the ledger row first, stages it (git add), then mints a single‑use nonce bound to the full HEAD SHA with a TTL. Ignores events that are not UserPromptSubmit; never mints on error.
lib/gate.pyLayer 1 (PreToolUse): shell parsing with quote‑aware splitting and cd tracking; allowlisted git subcommands; unique‑prefix option matching; default deny for git hidden in other commands; real‑path file guards; commit / push / tag rules. Layer 2: --git-hook (pre‑commit, pre‑merge‑commit, needs a 60‑second ticket) and --pre-push (every pushed commit's parent must match an authorizing ledger row). Any exception fails closed.
lib/swarmgit.pyStore in .git/plan-swarm/ (readable by git hooks, shared by worktrees, not committed); atomic writes; tolerant readers; race‑free nonce consume; tickets; per‑version tag allowances; activation marker; ledger read/write.
lib/health.pyHeartbeat plus --status. Running it through Bash fires the gate first, so a fresh heartbeat proves the hooks are live; stale means "enforcement off".
lib/swarmdoc.pyFinds the fenced JSON block of plans/swarm.md by its tag, validates every key, and matches path globs. No YAML dependency, because hooks run on the user's plain python3.
templates/git-hooks/*Thin shell wrappers that run the store's copy of gate.py (refreshed each session). PLAN_SWARM_STORE is honored only under PLAN_SWARM_TEST=1.

The central rule, as enforced in check_commit: a plans‑only change may use an intent/spec/plan approval for its milestone; anything else needs approve commit; in pr mode only on swarm/{m}; WIP only inside a linked worktree under .swarm/worktrees/.

B · Hardening from the security review

An independent adversarial review of the first gate reproduced bypasses and fail‑open paths. All are fixed in the commit; each has a test in test_security.py.

IDFindingFix
C1An agent could run approve.py itself and mint an approval.Commands mentioning control‑plane internals are refused; approve.py acts only on UserPromptSubmit.
C2Approvals forged via cd .git, variables, symlinks, .GIT.Real‑path resolution (case‑insensitive on macOS); no access to the git directory; variable targets refused.
C3Deleting plans/swarm.md switched the gate off.Activation marker; missing config fails closed; swarm.md and its folders protected.
C4bash -c, eval, xargs, aliases, GIT_CONFIG_* hid git.Subcommand allowlist; config and env tricks refused; default deny for git inside other commands.
C5–C6WIP pushed into swarm/{m}; -c remote.origin.push pushed main.WIP only in linked worktrees; explicit same‑name pushes; -B/-C/fetch‑into‑refs refused; pre‑push hook checks every commit.
H1–H3Crashes allowed the call; invalid config enforced little; merges and pulls bypassed pre‑commit.Fail closed (exit 2); full checks with defaults; merge only --squash, pull only --ff-only, pre-merge-commit hook.
H4–H8Abbreviations (--amen, --del, -uf); plans approvals committing code; gh pr merge; plugin and settings writable.Prefix‑aware options and clusters; ticket bound to kind and paths; gh gated; plugin and settings protected.
M1–M8Dispatch evasion; burnt nonces; races; empty HEAD; tag targets; multi‑use tag pushes; the hook suggesting --no-verify.Robust dispatch match; atomic consume; strict full‑SHA binding; tags on HEAD only; per‑version allowances; no bypass hints.
Threat model, stated in code and docs: the local layers guard against well‑meaning agents that try to unblock themselves. They are not a sandbox against a determined adversary with shell access. Branch protection, the CI ledger job, and code‑owner review are the authority.

Not in this change
